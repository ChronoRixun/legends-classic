# sound

## SUMMARY
I built a working XML1 Xbox to XML2 PC sound-bank converter. All 5 nyc1 banks are converted and checked, and so is every other XML1 bank (216 of 216). The ZSND container is the same design on both platforms: a 0x64-byte header with 7 tables {count, keys, entries}. Only two entry sizes differ (samples 28 vs 24 bytes, files 84 vs 76 bytes). Sound entries (24 bytes), sound hashes and ZTRK track bytecode carry over byte for byte. My parser (zsnd.py) reads all 562 banks from both games with every offset and size consistent. The only failure is XML2's own boss4_m.zsm, which ships malformed. Audio: Xbox uses Xbox-ADPCM, 36-byte blocks where each block gives the header sample plus nibbles 0..62. I pinned this model down against identical recordings shipped in XML2 (r=0.999 at lag 0). XML2 PC plays only one codec, which it decodes itself in XMen2.exe (not libIGAudio or the plugins): headerless continuous IMA ADPCM, format 0x6a. In-memory .zsm banks also accept raw 16-bit PCM; streamed .zss banks are always read as IMA. The converter decodes and re-encodes with a beam-search IMA encoder. Median per-bank SNR against the Xbox decode is 31.5 dB, music 35-60 dB, worst single short transient 17.2 dB. A lossless PCM mode exists for .zsm banks. Sounds are looked up by name hash: PJW/ELF over upper-cased chars (XMen2.exe 0x590280, same function in XML1). Names starting with death_style* or zone_sh* get '<zone soundfile>/' prepended. The engine checks tracks, then sounds, then '/***RANDOM***/n' variants. Both games load x_common and x_voice globally, soundfile -> <zone>_{m,a,c,v,d} per zone, and sounddir -> <dir>.zsd per character. XML1 names character sounds 'character/<dir>/...' where XML2 expects 'char/<dir>/...', so the converter adds char/ aliases. 19 XML1 bank filenames collide with XML2 files; merge_zsnd.py merges them with XML2's entries winning. An offline simulation of XML2's lookup resolves 72/73 names used by the nyc/alison zones and their conversations, and 5295/5586 (94.8%) across all 149 XML1 zone packages. Every miss is also missing from XML1's own banks. For in-game testing, copy research/sound/out/ima/eng/n/y/nyc1_{a.zss,c.zss,d.zsm,m.zsm,v.zss} into xml2_test/Sounds/eng/n/y/. Nothing is overwritten. Also add out/ima/eng/g/r/grso_m.zsm once grso_riot (sounddir="grso_m") exists in npcstat.

## FINDINGS
- [high] ZSND header (both platforms): 0x00 magic[8] ('ZSNDPC  ' / 'ZSNDXBOX'), 0x08 u32 file_size (PC exact, Xbox rounded up to 0x800), 0x0C u32 header_size (end of tables+ZTRK blobs; PC = first audio offset), 0x10 7 x {u32 count, u32 keys_off, u32 entries_off}: T0 sounds, T1 samples, T2 files, T3 unused, T4 tracks, T5/T6 unused. Keys = count x {u32 hash, u32 entry_index} sorted ascending (engine binary-searches). Tables are contiguous from 0x64.
    EVIDENCE: research/sound/zsnd.py parses all 346 XML2 + 216 XML1 banks; the XML2 loader XMen2.exe 0x594e50 relocates header fields 0x14/0x18/0x20/0x24/0x2c/0x30/0x38/0x3c/0x44/0x48/0x5c/0x60; binary search at 0x595720 (T0) and 0x595780 (T4)
- [high] Entry sizes: sound 24/24 (identical layout: u16 sample, u16 0x1000, u8 vol 0x7f, u8 0, u8 b6, ...), sample PC 24 / Xbox 28 (u16 file, u8 flags, u8 0, u32 rate, zero tail), file PC 76 {off,size,fmt,name[64]} / Xbox 84 {off,size,fmt,0,0,name[64]}, track 16 {u8 vol, u8 0, u8 initSound 0xff, u8 T6idx 0xff, u32 0, u32 ztrk_off, u16 0, u16 bankid(runtime)}. Sample flags: 0x02 stereo, 0x04 8-bit (never set), 0x01 loop, 0x20 on '_c' combat music (engine: 2 stream sub-voices).
    EVIDENCE: survey3.py field histograms over all banks; engine uses flags at 0x5950a8/0x595250/0x595ac0 (0x02) and 0x59610a (0x20); track entry use at 0x592d9d..0x592e16
- [high] Counts. XML2 PC: 346 banks, 9055 sounds, 9016 samples/files, 1 track, 725,353,687 audio bytes, every file format 0x6a, 84 stereo. XML1 Xbox: 216 banks (15 empty 100-byte banks), 6544 sounds, 6528 samples/files, 466 ZTRK tracks in 40 banks, 614,829,312 audio bytes, format 1 = mono (6467), format 3 = stereo music (61), all 2 KB aligned, every size an exact multiple of 36*channels. Each file is used by exactly one sample on both platforms.
    EVIDENCE: python research/sound/zsnd.py ; python research/sound/survey_audio.py
- [high] XML2's own b/o/boss4_m.zsm is malformed. It is the only PC bank with a track: the track entry offset is 0x01000000, there is no ZTRK blob, and the last sample runs 68 bytes past EOF. PC-side tracks were never exercised in shipped XML2 data.
    EVIDENCE: zsnd.py BAD report for Sounds/eng/b/o/boss4_m.zsm; explore2.py dump: t4 raw 7f00ffffffff0c0000000001 01010008
- [high] Suffix meaning. _a = ambient music, one stereo stream keyed 'music/<zone>_a'. _c = combat music 'music/<zone>_c' (flag 0x20). _d = death-style/destructible sounds keyed '<zone>/death_style(s)/...'. _m = zone SFX ('<zone>/zone_shared/...', 'object_ambi/...'). _v = zone voice lines 'voice/<speaker>/<line>'. Character banks are '<sounddir>.zsm' (the _m is part of the sounddir). .zsm = memory-resident: every sample is decoded into a DirectSound buffer at load. .zss = streamed: only the header stays resident. The loader tries .zsm first, then .zss.
    EVIDENCE: XMen2.exe 0x592050 (suffix list 'm','a','c','v','d' at 0x59228d; 'd' skippable via +0xd0b2), 0x591380 (replaces last char with 'm' mode 1, then 's' mode 0); names_xml1.json/names_xml2.json (resolve.py)
- [high] The XML2 PC codec is implemented in XMen2.exe itself, not in libIGAudio or plugins/codecs. XMen2.exe does not import libIGAudio.dll and loads DSOUND.DLL/DirectSoundCreate dynamically (0x594280). The format is headerless continuous IMA ADPCM: state starts at pred 0 / index 0 and is never reset. Mono is low nibble first; stereo packs L in the low nibble and R in the high nibble of each byte. For .zsm, format 0x6a is decoded at load (buffer = size*4) and any other format is memcpy'd as raw PCM. .zss streams are always IMA-decoded.
    EVIDENCE: decoders 0x616770 (mono) / 0x616880 (stereo), wrappers 0x616a00/0x616a30; IMA tables at VA 0x6e95a8/0x6e9588; format check 0x595137 (only code checking 0x6a); stream open 0x595aa0 'or [esi+0x14],1' unconditional; stream decode 0x595b20
- [high] Xbox ADPCM block model: each 36-byte block per channel (s16 pred, u8 index, u8 0, 32 data bytes) yields 64 samples = the header sample followed by the decodes of nibbles 0..62; nibble 63 is not played. Stereo blocks are 72 bytes with 4-byte L/R interleave. Only this model time-aligns with identical recordings XML2 ships as PC IMA (dmg_stun, under_momentum, whoosh_* etc.: r=0.998-0.9997 at lag 0). The 64-nibble model is off by 1 sample; the 65-sample model drifts. It also matches ffmpeg's adpcm_ima_xbox output.
    EVIDENCE: research/sound/xcompare.py and blockmodel.py (junction roughness ratio 1.00 vs 1.55); ffcheck.py
- [high] Name hash = PJW/ELF over toupper(chars) of the name after '\'->'/', with chaining. XML1 uses the same function. For example hash('music/abug_a')=0x067de251 matches XML2 abug_a.zss and hash('music/nyc1_a')=0x07171c51 matches XML1 nyc1_a.zss. Random variants are separate entries keyed hash('/***RANDOM***/n', seed=hash(name)). T1/T2 keys are opaque build-path hashes that no lookup uses.
    EVIDENCE: XMen2.exe 0x590280 (toupper thunk 0x6723ce -> MSVCR71!toupper), normaliser 0x5924e0/0x5902d0; research/sound/zhash.py; resolve.py explains 71.1% of all XML1 keys (100% for nyc1 d/m/a/c)
- [high] XML2 lookup: if a zone soundfile is loaded and the name _strnicmp-matches 'death_style' (11 chars) or 'zone_sh' (7 chars), the engine prepends '<soundfile>/'. The prefix is the soundfile string copied with strncpy(10), so it must be under 10 chars. Then, per loaded bank, it tries the track table, the sound table, then RANDOM/0. XML1 data uses 'death_styles/...', which still matches XML2's 11-char test and yields keys identical to XML1's (e.g. 'nyc1/death_styles/ds_wood_m' is an XML1 track key).
    EVIDENCE: XMen2.exe 0x590bd0 (strings 'death_style' 0x69d2d8, 'zone_shared' 0x69d2cc, '%s/%s'), 0x590e50, 0x5905e0; simlookup.py on converted nyc1 banks: 72/73 names from maps/nyc/alison/*.eng + conversations/nyc/alison/*.eng resolve (the miss 'death_styles/t_roof' is absent from XML1's own banks too)
- [high] Bank loading. Global: x_common.zsd and x_voice.zsd. Per zone: world entity soundfile -> sounds/eng/<c1>/<c2>/<soundfile>_{m,a,c,v,d}. Per character: herostat/npcstat sounddir -> <sounddir>.zsd. XML1 uses the same scheme but its root is 'sounds/ZSDs/' with no language directory.
    EVIDENCE: XMen2.exe table 0x69d064 (x_common.zsd, x_voice.zsd) used by 0x58f2a0/0x591200; 0x592050 (soundfile), 0x5923e0 -> 0x590a10 '%s.zsd' (sounddir attr read at 0x4b9c40); path builder 0x590a70 + 0x592b00 (two-letter subdirs); xbe strings 'sounds/ZSDs/', '%s_%c.zsd'
- [high] Character sound prefix differs: XML1 builds 'character/<dir>/<event>' (xbe 'character/' 0x3bbef8, 'character/%s/flyend') and XML2 builds 'char/<dir>/<event>' (exe 'char/' 0x684180, 'char/%s/flyend'). Event names come from shared_sounds SOUNDTABLE (pain, death, jump, land, pickup, throw...). Converted character banks therefore get extra alias entries under 'char/...': 645 aliases across the full batch.
    EVIDENCE: resolve.py names (e.g. XML1 'character/grso_m/pain/***RANDOM***/0..2' vs XML2 'char/cyclop_m/pain/***RANDOM***/0..2'); simlookup: char/grso_m/{pain x3,death,jump,land,pickup,throw} resolve in converted grso_m.zsm
- [high] XML1 death sounds are ZTRK tracks that layer 2-5 variant samples with delays; XML2 uses single pre-mixed samples. The ZTRK interpreter in XMen2.exe is instruction-for-instruction identical to XML1's (first 165 normalized instructions match up to ret). Grammar: event byte b, code=b&7 selects 0/1/4/1/2/5/4/8 prefix bytes, type=b&0xF8 selects 2/1/2/2/4/0 arg bytes. Controller 0x10 cmd 4 = select sound by 1-byte index. All 466 XML1 tracks parse exactly and all sound references are in range.
    EVIDENCE: XMen2.exe 0x593610 (jump tables 0x59382c/0x593878), 0x592e50 (cmd table 0x592f68, cmd 4 -> 0x5956c0 = &sounds[idx]), 0x592d9d (start = entry+8+4); xbe 0x17f1f3 vs exe 0x193623 (cmpcode.py); research/sound/ztrk.py
- [high] The converted nyc1 banks pass strict re-parse. Sound entries, keys and ZTRK blobs are verbatim, and every file decodes to exactly the Xbox sample count. SNR vs Xbox decode (beam encoder): nyc1_a 44.5 dB, nyc1_c 36.5 dB, nyc1_d median 29.8 / worst 21.1, nyc1_m median 28.4 / worst 22.7, nyc1_v median 31.1 / worst 24.7. The --zsm-pcm variant is lossless for d/m.
    EVIDENCE: python convert_zsnd.py --batch ... --only nyc1 (verification inside convert()); wavcheck.py stats; WAV pairs in research/sound/wav/
- [high] The full batch converted all 216 XML1 banks (192 verified in-run, 24 re-verified by verify_out.py) with 466 tracks preserved. Median per-bank SNR is 31.5 dB (min median 24.8); the worst single file is 17.2 dB (a short transient in morl_p_m). Simulating XML2 lookups against the converted banks gives the same coverage as against the XML1 originals: 5295/5586 names (94.8%) over 149 zone packages. The misses are also absent from XML1's banks, e.g. character/sentin_m/power4.
    EVIDENCE: research/sound/out/all_ima/eng/_convert_report.json, verify_out.py output, zone_coverage.txt and zone_coverage_converted.txt
- [high] 19 XML1 bank filenames collide with XML2 files: x_common, x_voice, menu_a, menu_c, beast_m, bishop_m (empty), blob_m, coloss_m, cyclop_m, danger_m, iceman_m, magnet_m, morl_c_m, morl_p_m, mystiq_m, night_m, pyro_m, storm_m, toad_m. Character-bank key sets are disjoint because of the char/ vs character/ prefixes. x_common shares 49 of 114 keys; x_voice shares 139 of 1716. merge_zsnd.py produced 18 merged banks that all parse strictly; XML2 entries keep their indices and XML1 track indices are remapped.
    EVIDENCE: research/sound/xml1_bank_usage.txt (COLLIDES column); out/merged/eng/_merge_report.json; python zsnd.py out/merged/eng -> 0 bad banks
- [medium] XML1 music is 44100 Hz stereo (flags 0x02 / 0x22) and streams at twice XML2's data rate. XML2 ships no stereo 44.1 kHz stream (only 41000 Hz mono in x_voice and 44100 Hz mono in deadpl_m.zsm). The stream reader stores the rate as u16, which fits 44100.

## RISKS
- ZTRK tracks (all XML1 death-style sounds, plus some character powers) run through an interpreter that is byte-identical to XML1's, but shipped XML2 PC data never had a working track (boss4_m's is corrupt). Playback on PC is therefore untested until nyc1 props are broken in game.
- XML1 music streams are 44100 Hz stereo; XML2 never streams stereo at 44.1 kHz. If music stutters or drops, add a 2:1 downsample to 22050 Hz (not implemented yet).
- Re-encoding IMA from IMA costs quality: median about 30 dB SNR against the Xbox decode, worst 17 dB on a few very short transients. The --zsm-pcm option is lossless for in-memory banks but relies on the raw-PCM path, which no shipped XML2 bank exercises.
- Character-bank aliases (character/ -> char/) only exist for keys whose names could be recovered: 71% of all XML1 keys, 89% for grso_m. An XML2 engine-generated event whose XML1 name was never recovered will stay silent.
- Copying out/all_ima's x_common/x_voice/menu_*/hero banks over XML2's files would break XML2's own sounds. Use out/merged instead. The merged x_voice.zss is 153 MB with 5873 sounds, larger than anything XML2 ships (header stays under 1 MB); untested.
- Zone soundfile names of 10+ characters make XML2 abort zone-sound loading (strncpy 10 check at 0x5920cb); all XML1 values are 6 characters or fewer.

    NOTE: My own parser (research/sound/verify/indep_parse.py) does not assume entry sizes; it infers them from the gaps between spans. Every non-empty table starts at 0x64, all keys are sorted in all 562 banks, and T3/T5/T6 have count 0 everywhere. PC header_size equals the first audio offset in all 346 banks; Xbox header_size < first audio in 200 banks because of 2 KB alignment. Loader 0x594eb8-0x594f1c relocates 0x14/0x18/0x20/0x24/0x2c/0x30/0x38/0x3c/0x44/0x48/0x5c/0x60 and never touches 0x50/0x54 (T5). The T0 search at 0x595730 reads 0x10/0x14/0x18; the T4 search at 0x595790 reads 0x40/0x44/0x48. Nothing searches T1 or T2.
- CONFIRMED: Entry sizes: sound 24/24, sample 24 PC / 28 Xbox, file 76 PC / 84 Xbox, track 16. Sample flags 0x01 loop, 0x02 stereo, 0x04 8-bit (never set), 0x20 combat music.
    NOTE: Inferred sizes: PC T0e=24, T1e=24, T2e=76 (all 346 banks); Xbox 24/28/84 (201 non-empty banks); Xbox T4e=16 (40 banks). ### plan problems
- The 94.8% zone coverage (5295/5586) misses script-played sounds. names_from() only matches attributes whose name contains 'sound' and calls of the form play*sound*(".."). XML1 scripts play sounds as sound("PLAY_SOUND", "<name>", ...) (154 calls), and none of them are counted. My per-zone check (verify/script_sounds.py): 83/104 zone-scoped script names resolve; the misses are mostly XML1 typos such as zone__shared and effets. Another 34 names sit in script dirs with no map, e.g. asteroid_m, mansion/dr_mag2 and mocap briefings. nyc/alison scripts: 13/13 resolve. 'filename="character/sentin_m/..."' attributes are also not counted.
- The coverage simulation loads every XML1 character bank at once and uses XML1's original hero banks for the 17 colliding sounddirs. Real play loads only the sounddirs of characters in the zone, and colliding hero banks resolve against XML2's files unless the merged versions are installed. The figure is an upper bound, not a drop-in prediction.
- XML1 world attributes ambientmusic/combatmusic appear in sewers2_1_2, sewers2_1_3, sewers1_1_2, arb2_2, arb2_3 and the demo maps. XMen2.exe has no such strings, so these per-zone music overrides are lost. Those zones will play <soundfile>_a/_c instead; this is not mentioned anywhere.
- Statements to correct: ffmpeg agreement is time-alignment only, not bit-exact; music SNR is 32.6-65.4 dB, not 35-60; the all_ima batch used encoder=auto (greedy for stereo music), not beam everywhere.
- Constraint missing from the plan: the .zsm loader builds WAVEFORMATEX with nBlockAlign=2 for 16-bit regardless of channel count (0x5950c3-0x5950d6). Stereo samples must never be placed in .zsm banks, IMA or --zsm-pcm. None are today; all stereo is in _a/_c .zss.
- The PCM .zsm fallback is sound at the load path: 0x595137 is the only 0x6a check in the whole exe. But 'lossless' means identical to this bitwise-IMA reference decode; ffmpeg's Xbox decoder rounds differently (max diff 11-36), so the true hardware output is unknown.
- Music auto-start from soundfile is plausible but unproven offline. No script in either game references music, and XML2 zones only carry soundfile. I could not find the caller of the music vtable method 0x477690 (slot 0x687944). Keep it as an in-game check, as the plan already does.
- The 44.1 kHz stereo stream risk is smaller than the plan states. The stream DirectSound buffer is at least 0x8dc00 bytes (0x596135), about 3.3 s at 44.1 kHz stereo 16-bit. The optional 2:1 downsample is probably unnecessary, pending the in-game test.
